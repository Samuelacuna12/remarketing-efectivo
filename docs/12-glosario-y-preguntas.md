# 12. Glosario y preguntas frecuentes

[Volver al índice](../README.md)

## Glosario práctico

| Término | Definición usada en esta guía | Precaución |
|---|---|---|
| Cliente | Persona o cuenta con una compra válida según la definición comercial | Registro o conversación no equivalen a compra |
| Prospecto | Persona o cuenta que todavía no cumple la definición de cliente | Puede requerir otra oferta y otra medición |
| Retargeting | Activación publicitaria basada en una interacción o relación previa | Una visita no prueba relación de compra |
| Remarketing a clientes | Programa para volver a vender a compradores mediante publicidad y comunicación permitida | El permiso es específico de finalidad y canal |
| Retención | Continuidad de la relación o actividad que el negocio ha definido | Hay que especificar qué cuenta como actividad |
| Segunda compra | Paso de una compra válida a otra dentro de un horizonte | No incluye dividir artificialmente el mismo pedido |
| Reposición | Compra para sustituir o reponer consumo de un producto | Cantidad y ritmo de uso cambian el momento |
| Cross-sell | Venta de algo complementario | Compatibilidad y necesidad son esenciales |
| Upsell | Paso a una opción de mayor alcance o valor | Debe mejorar algo relevante para el cliente |
| Winback | Recuperación de clientes inactivos según un criterio explícito | No toda ausencia de compra significa abandono |
| Cohorte | Grupo con una característica o fecha de entrada común | Compara grupos con igual tiempo de observación |
| RFM | Clasificación por recencia, frecuencia y valor monetario | No es una predicción causal ni una identidad permanente |
| Recencia | Tiempo desde la última acción definida | Especifica compra, entrega u otra señal |
| Frecuencia de compra | Número de compras válidas en una ventana | No es frecuencia publicitaria |
| Frecuencia publicitaria | Impresiones por persona alcanzada en el periodo informado | La media oculta diferencias individuales |
| Audiencia | Población definida para activar o analizar | En una plataforma puede ser señal y no restricción |
| Supresión | Regla que impide una activación improcedente | Debe llegar a los sistemas que ejecutan |
| Holdout o control | Grupo asignado a no recibir la intervención estudiada | Define qué comunicaciones habituales conserva |
| Tratamiento | Grupo asignado a la intervención | Incluye también personas no alcanzadas al analizar intención de tratar |
| Incrementalidad | Diferencia causada por añadir la intervención | La atribución no la demuestra por sí sola |
| ROAS atribuido | Ingresos atribuidos divididos por gasto publicitario | No descuenta necesariamente costes ni ventas que ocurrirían sin campaña |
| Contribución | Ingreso neto menos costes variables definidos | Especifica si incluye gasto de campaña |
| LTV | Valor acumulado o esperado de una relación durante un horizonte | Usa contribución y supuestos explícitos, no ingresos infinitos |
| CAC | Coste definido de adquirir un cliente nuevo | No llames adquisición a cada recompra |
| UTM | Etiquetas de URL para identificar origen y campaña | No incluyas identidad personal ni información sensible |
| Feed | Archivo o conexión de productos o servicios para un proveedor | IDs, precio y stock necesitan mantenimiento |
| Coincidencia | Vinculación de datos autorizados con cuentas en una plataforma | No equivale a alcance ni a consentimiento |
| Idempotencia | Procesar un mismo evento repetido sin duplicar la acción de negocio | Fundamental ante reintentos de automatización |
| Entregabilidad | Capacidad del mensaje de llegar en condiciones adecuadas | Entregado, leído y convertido son pasos diferentes |
| Contaminación | Exposición del control a la intervención u otra diferencia no prevista | Registrar lo ocurrido y limitar la conclusión |

## ¿Con qué estrategia empiezo?

Con una necesidad clara, un segmento identificable y una economía comprensible. La reposición puede ser apropiada para consumibles; un complemento, para productos con ecosistema; la renovación, para servicios recurrentes. Si hay mala experiencia pendiente, empieza por resolverla. La estrategia más fácil de lanzar no siempre es la de mayor valor.

Evalúa disponibilidad de datos, permisos, volumen, margen, capacidad de atención y tiempo de decisión. Usa la matriz de priorización y elige un piloto que pueda operar una persona responsable. No necesitas activar simultáneamente todos los canales descritos en el manual.

## ¿Cuánto presupuesto debo dedicar?

No existe un porcentaje universal. Parte del tamaño alcanzable, del coste previsto, del margen y del valor adicional que tendría que producirse. Define cuánto puedes arriesgar para aprender y una fecha de evaluación. Si el presupuesto es demasiado pequeño para responder la pregunta comercial, reconoce que el piloto comprobará operación, no rentabilidad con precisión.

Si ya haces campañas, separa captación de clientes nuevos, retención y actividad mixta en la planificación, aunque la estructura técnica no sea perfectamente separable. El nombre de una campaña no prueba en qué población se gastó el dinero.

## ¿Cuántos impactos debe recibir un cliente?

Los suficientes para aportar utilidad sin deteriorar la relación, pero ese número depende del canal, periodo, producto y contexto. No traslades una regla de frecuencia de una marca a otra. Observa contribución marginal, quejas, bajas, silencios y saturación. Coordina las automatizaciones para que un mismo cliente no reciba al mismo tiempo mensajes contradictorios.

En publicidad no siempre puedes imponer o conocer una secuencia individual exacta. En canales directos puedes controlar mejor los envíos, pero también debes respetar permisos, reglas de plataforma y preferencias.

## ¿Debo ofrecer descuento a todos?

No. Primero identifica la barrera: desconocimiento de compatibilidad, fricción de compra, envío, disponibilidad, falta de necesidad o mala experiencia. Un descuento puede reducir margen de compras que habrían ocurrido igual y enseñar a esperar promociones. Prueba alternativas como ayuda, acceso, conveniencia, paquete útil o una mejora de servicio que realmente puedas cumplir.

Cuando pruebes descuentos, incluye su coste en el ingreso neto y no lo vuelvas a restar por duplicado. Evalúa compra posterior sin incentivo y el efecto sobre otras categorías, no solo la venta inmediata.

## ¿Excluyo a todos los compradores de todos los anuncios?

No. Los compradores son precisamente la población de un programa de recompra. Excluye a quien no deba recibir **ese mensaje**: alguien que acaba de comprar el complemento no necesita verlo otra vez; quien devolvió el producto base no debe recibir la misma recomendación; una baja impide las activaciones correspondientes. En captación de nuevos clientes puedes necesitar otra política de exclusión, revisada según la función disponible.

Define reglas por estrategia y una supresión común de mayor prioridad. Una lista genérica llamada “compradores” no resuelve todos los casos.

## ¿Puedo usar un número de teléfono porque ya me compró?

La existencia de una compra no demuestra autorización para cualquier mensaje, finalidad o compartición. Revisa qué se informó y autorizó, qué reglas aplica el canal y qué obligaciones corresponden al mercado. Un aviso operativo de entrega y una promoción son usos distintos. Conserva evidencia y ofrece una salida efectiva. Consulta los capítulos de CRM y privacidad antes de activar.

## ¿Qué hago si mi audiencia es pequeña?

Evita subdividirla hasta dejar segmentos sin entrega ni aprendizaje. Prioriza una comunicación útil por un canal permitido y una revisión cualitativa de respuestas. Puedes mejorar la calidad del dato o acumular un periodo de observación más largo, si es razonable para el ciclo comercial. No compres listas ni incluyas personas sin fundamento para inflar el tamaño.

Una base pequeña puede ser valiosa económicamente, especialmente en B2B, pero no permite conclusiones estadísticas fuertes solo por tener un gran ticket.

## ¿Cuál plataforma es mejor?

La que puedas usar de forma adecuada para el objetivo, la población y el proceso de venta. Una búsqueda expresa intención; una pieza visual puede enseñar; un email puede explicar; una conversación puede resolver una duda. Selecciona por necesidad y capacidad de ejecución. La guía desarrolla Meta y Google por su utilidad en estos escenarios, sin afirmar que sean obligatorios ni los únicos canales posibles.

## ¿Cómo sé si una automatización funciona?

Prueba casos de entrada, salida, reintento, error y revocación. Verifica que el mensaje se registre una vez, que una compra posterior detenga el paso inapropiado, que la baja se propague y que un error active una alerta. Después valida ventas y experiencia. Un panel sin errores no prueba que las reglas comerciales estén bien.

## ¿Por qué difieren los números del CRM y de la plataforma?

Porque pueden medir cosas distintas: clientes frente a usuarios, pedido pagado frente a evento de navegador, atribución frente a venta total, bruto frente a neto y periodos diferentes. Antes de reconciliar, alinea definiciones, moneda, zona horaria y fecha de maduración de devoluciones. Las diferencias restantes se investigan; no se corrigen cambiando números sin trazabilidad.

## ¿Qué debería revisar cada semana?

Salud de datos, permisos y supresiones; gasto y entrega; disponibilidad de productos; atención a respuestas; ventas válidas, devoluciones y contribución; presión de contacto y quejas; cambios del experimento y próximos pasos. Si el ciclo de compra es largo, no fuerces una decisión de negocio semanal, aunque mantengas la revisión operativa.

## ¿Qué significa escalar con prudencia?

Aumentar inversión o población después de comprobar valor adicional y capacidad de atenderlo, manteniendo controles. El resultado de una audiencia pequeña no se extrapola linealmente al resto de clientes. Documenta qué cambia al ampliar: categoría, antigüedad, margen, mezcla de productos o canal. Mantén una forma de detectar cuándo deja de valer la pena.

## ¿Qué no debo publicar en un repositorio público?

Ningún dato real de clientes, listas de coincidencia, conversaciones privadas, pedidos individuales, tokens ni credenciales. Tampoco un hash de un identificador personal como si fuera anónimo por defecto. Comparte reglas, ejemplos sintéticos, indicadores agregados y fuentes públicas. Las herramientas de este repositorio no necesitan subir datos a un servicio externo.
